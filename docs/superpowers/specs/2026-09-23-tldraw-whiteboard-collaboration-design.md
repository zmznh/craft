# 阶段6：tldraw 白板实时协同

## 目标

为现有 tldraw 白板增加通过分享链接加入的实时多人协作。沿用 tldraw 官方同步协议，部署独立自托管 WebSocket 服务；保留现有白板页面和 `Whiteboard.data` 快照作为恢复检查点。

## 已确认的产品决策

- 白板分享默认关闭，由所有者主动开启。
- 所有者可设置分享权限为关闭、查看或编辑，并可撤销分享。
- 持有效查看权限链接的访问者可匿名查看。
- 编辑权限必须登录。编辑链接持有者完成登录后才能编辑。
- 白板所有者始终有编辑权限。
- 撤销分享后，新的连接必须被拒绝，已经通过该分享加入的活动连接也必须断开。

## 系统边界

- Next.js 继续负责会话、所有权验证、分享配置、凭证签发和白板页面。
- 独立 Node.js WebSocket 服务集成 tldraw 官方同步协议，按白板 ID 管理实时房间。
- 浏览器通过官方 `@tldraw/sync` 客户端连接房间；服务端使用官方 `@tldraw/sync-core` 房间能力。
- Next.js 分享配置变更后，通过带服务端认证的内部通知调用同步服务，使其失效相关凭证并断开依赖该分享的活动连接；不能暴露可被浏览器调用的管理接口。
- 不复用 Hocuspocus/Yjs 文档协议。现有文档协作服务继续服务 TipTap 文档，不承载 tldraw 房间。

## 授权模型

分享配置至少包含白板 ID、不可预测的分享 token、权限级别及撤销/启用状态。持久化结构可采用白板字段或独立分享记录，具体选择由实现规划根据当前 Prisma contract 的约束确定；外部行为保持一致。

连接流程：

1. 客户端请求 Next.js 凭证端点，提供白板 ID 和分享 token。
2. Next.js 检查分享存在、未撤销且权限足够；编辑凭证还要求有效登录会话。所有者身份可绕过分享链接权限，但不能绕过白板资源归属校验。
3. Next.js 签发短时、限定白板 ID、角色和分享版本的签名凭证。凭证不得包含数据库密钥或其他服务端秘密。
4. WebSocket 服务验证签名、有效期、房间 ID 和角色，只允许凭证声明的访问级别。查看者不能写入共享状态；不得信任客户端传来的角色字段。
5. 分享权限变更或撤销时递增分享版本/使当前凭证失效，并断开依赖该分享的活动连接。所有者自己的连接不受分享撤销影响。

匿名访问不创建伪造的用户会话。同步层使用独立访客身份标识，避免暴露个人资料；访客身份只用于本房间 presence。

## 状态同步与持久化

- tldraw 同步房间是在线编辑期间的权威实时状态；更新由官方同步协议广播，不再由多个浏览器通过整份 JSON 快照互相覆盖。
- 房间首次创建时读取 `Whiteboard.data` 并恢复 tldraw snapshot；旧版快照必须继续可加载。
- 房间变更触发节流检查点，将最新 snapshot 写回该白板的 `Whiteboard.data`。写入必须按白板 ID 定位并保留现有所有权边界。
- 服务正常关闭时尽力 flush 所有待写检查点。数据库写入失败必须记录服务端错误，不能静默标记为已持久化。
- 健康运行时的目标是变更后约 1 秒内提交检查点；进程突然退出时，最近一次成功检查点之后的数据可能丢失。数据库不可用时不承诺固定数据丢失上限。
- 具体同步 SDK 存储接口、快照格式及回调须以锁定版本文档/类型为准，不假设通用数据库适配器已存在。

## 页面行为

- 原有 `/whiteboards/[id]` 仍加载白板；所有者可从白板页面访问分享设置、复制链接和撤销链接。
- 有效分享链接打开白板协作视图；查看权限下画布不可编辑，编辑权限但未登录时提示登录，登录后恢复到原白板链接并重新申请编辑凭证。
- 连接状态至少能区分连接中、已连接、断开/重连和授权失效；授权失效不得无限重试。
- 本阶段不要求另建成员邀请系统、评论、历史回放或白板级细粒度成员表。

## 许可与依赖门槛

当前项目安装 `tldraw` 5.4.2，但未安装 `@tldraw/sync` 或 `@tldraw/sync-core`。官方文档给出的客户端与服务端包名/API 可作为调研起点，正式实现须匹配与 tldraw 5.4.2 兼容的版本并锁定依赖。

本地 `tldraw/LICENSE.md` 将许可指向 tldraw SDK license，官方同步文档没有完整解释生产自托管许可条件。实现前须核实当前项目用途及部署方式符合 SDK 许可；若不符合，暂停依赖接入并重新评估技术路线，不得默认许可允许商用部署。

## 验收

1. 两个浏览器同时打开同一白板；一端创建、移动、删除图形，另一端实时看到一致结果。
2. 不同白板的房间状态互相隔离。
3. 分享关闭时，匿名和非所有者均无法建立房间连接；已撤销链接不能申请新凭证。
4. 查看链接可匿名进入，但尝试创建、移动、删除内容均不改变共享白板状态。
5. 编辑链接的匿名访问者被要求登录；登录后可编辑，另一个客户端实时收到更新。
6. 撤销分享会断开现存分享连接；撤销后不能重新连接。所有者仍可访问和编辑。
7. 刷新页面及同步服务重启后，最后成功写入的检查点可恢复；旧格式 `Whiteboard.data` 仍可加载。
8. 凭证过期、签名无效、房间 ID 不匹配、白板删除/无权限等情况均拒绝连接，不泄露白板快照。
9. 现有白板快照保存、白板删除、文档编辑协作及相关构建/测试不回归。

## 不在本阶段

- 组织/团队成员目录与指定用户邀请。
- 细粒度白板角色以外的评论/建议权限。
- 离线编辑合并、版本历史与操作回放。
- 多实例横向扩展、分布式房间协调与高可用部署。
- 新增媒体资产托管或白板外部嵌入能力；若官方协议运行所必需的最小资产适配，需在实现计划中单独标明。
